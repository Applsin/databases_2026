![][image30]

Вариант NOT IN использует Index Scan по flights\_pkey и hashed SubPlan, построенный последовательным сканированием ticket\_flights. Зарегистрированы shared hit=10086 и shared read=10663: использовались кеш PostgreSQL и чтение через ОС, которое не обязательно означает физическое чтение диска, временные файлы в плане не зарегистрированы. Время планирования составило 0,213 мс, выполнения  592,328 мс.

Вариант NOT EXISTS преобразован в Hash Right Anti Join с последовательным сканированием обеих таблиц, без использования индексов. Зарегистрированы shared hit=10254 и shared read=10298, хеш-таблица построена в одном пакете в памяти (5128 КБ), сортировка quicksort также выполнена в памяти (3321 КБ), без временных файлов. Время планирования составило 0,326 мс, выполнения  605,645 мс, поэтому этот запуск не показал ускорения относительно NOT IN.

Anti Join оставляет рейсы, для которых нет соответствующих записей бизнес-класса. Если подзапрос NOT IN содержит NULL, то для значений без совпадений результат сравнения становится UNKNOWN и строки отбрасываются, NOT EXISTS с проверкой равенства этой проблемы не имеет. В данной базе ticket\_flights.flight\_id объявлен NOT NULL, поэтому такая опасность для исходного запроса отсутствует.
