## 4. Анализ кэша и прогрев

1. Выполните `JOIN` таблиц `flights` и `ticket_flights` с `EXPLAIN (ANALYZE, BUFFERS)`.
   Пример запроса:

   ```sql
   EXPLAIN (ANALYZE, BUFFERS)
   SELECT f.flight_id, f.flight_no, tf.ticket_no, tf.amount
   FROM flights f
   JOIN ticket_flights tf ON f.flight_id = tf.flight_id
   ```

## 6. Сравнение индексов (синтетический кейс)

1. Создайте таблицу:

   ```sql
   CREATE TABLE test_skew (
       id SERIAL PRIMARY KEY,
       payload TEXT
   );
   ```

2. Вставьте 100 000 строк:

   ```sql
   INSERT INTO test_skew (payload)
   SELECT 'payload_' || i FROM generate_series(1, 100000) AS i;
   ```

3. Создайте два индекса:

   ```sql
   CREATE INDEX idx_test_skew_btree ON test_skew(id);
   CREATE INDEX idx_test_skew_brin  ON test_skew USING BRIN(id);
   ```

4. Сравните размеры:

   ```sql
   SELECT relname, pg_size_pretty(pg_relation_size(oid))
   FROM pg_class
   WHERE relname LIKE 'idx_test_skew_%';
   ```

**В отчёте:** объясните, почему BRIN занимает меньше места. В каком сценарии (OLTP поиск по ID или сканирование диапазона логов) использовать B-Tree, а в каком BRIN? Опишите, как помогли бы `fillfactor` и партиционирование.

## 7. Диагностика `pg_stat_statements`

1. Включите расширение (при первом запуске потребуется preload: `ALTER SYSTEM SET shared_preload_libraries = 'pg_stat_statements';` + `docker restart pg16_check` — см. семинар 7, раздел 6):

   ```sql
   CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
   ```

2. Сбросьте статистику:

   ```sql
   SELECT pg_stat_statements_reset();
   ```

3. Выполните любой тяжёлый аналитический запрос из предыдущих пунктов.
4. Найдите его в топе самых медленных:

   ```sql
   SELECT query, calls,
          total_exec_time::numeric(10,2) AS total_ms,
          mean_exec_time::numeric(10,2)  AS avg_ms,
          shared_blks_read, temp_blks_written
   FROM pg_stat_statements
   ORDER BY total_exec_time DESC
   LIMIT 10;
   ```

**В отчёте:** приложите вывод статистики по запросу (количество вызовов, среднее время, `shared_blks_read`, `temp_blks_written`). Сделайте вывод об эффективности.
