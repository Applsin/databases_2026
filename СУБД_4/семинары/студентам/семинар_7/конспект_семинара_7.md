# Конспект семинара №7. Управление памятью, I/O и перекосы индексов

## 1. Главная идея

Реляционная БД — не «чёрный ящик». Понимание перемещения данных между диском, ОЗУ и CPU критично для предотвращения сбоев (I/O Stall, OOM) и обеспечения производительности.

## 2. Ключевые термины

- **Буферный пул (`shared_buffers`)** — разделяемая ОЗУ PostgreSQL для копий страниц (8 КБ).
- **`EXPLAIN (ANALYZE, BUFFERS)`:**
  - `shared hit` — страница в `shared_buffers` (быстро).
  - `shared read` — страницы нет в кэше СУБД, чтение через ОС/диск (медленно).
  - `temp read/write` — сброс сортировки/хэша на диск из-за нехватки `work_mem`.
- **LWLocks (Latches)** — легковесные блокировки внутренних структур памяти (микросекунды).
- **Latch Contention** — конкуренция за защёлку, когда множество процессов лезут в одну страницу.
- **Index Skew / Hot Spot** — все вставки идут в правый лист B-Tree (монотонные ключи).

## 3. Борьба с перекосами

| Стратегия | Суть | Плюс | Минус |
|---|---|---|---|
| UUIDv4 | Случайные ключи | Нет hot spots | Много page splits, bloat |
| UUIDv7/ULID | Время + случайность | Несколько правых листьев | Нужна поддержка генерации |
| BRIN | Мин/макс по блокам | Весит мало, нет перекосов | Только упорядоченные данные |
| FILLFACTOR | Оставляет место на странице | Меньше splits | Индекс больше |
| Partial Indexes | Индекс по части данных | Компактнее | Только предсказуемые запросы |
| Partitioning | Разбиение таблицы | Hot spot распределяется | Сложнее администрировать |

## 4. Pre-flight Checklist (перед тяжёлым запросом)

```sql
-- 1. Текущая нагрузка
SELECT state, count(*)
FROM pg_stat_activity
WHERE datname = 'demo'
GROUP BY state;

-- 2. Актуальность статистики
SELECT relname, last_analyze, last_autoanalyze, n_mod_since_analyze
FROM pg_stat_user_tables
WHERE relname = 'ticket_flights';

-- 3. Принудительный ANALYZE
ANALYZE ticket_flights;

-- 4. Прогрев кэша
CREATE EXTENSION IF NOT EXISTS pg_prewarm;
CREATE INDEX IF NOT EXISTS ticket_flights_flight_id_amount_idx
    ON ticket_flights(flight_id, amount);
SELECT pg_prewarm('ticket_flights');
SELECT pg_prewarm('ticket_flights_flight_id_amount_idx');
```

## 5. Управление памятью запроса (`work_mem`)

`work_mem` (по умолчанию 4 МБ) — память на одну операцию (sort, hash join) внутри запроса.

```sql
-- до увеличения: Sort Method: external merge Disk: ...
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM ticket_flights ORDER BY amount DESC;

SET work_mem = '256MB';

-- после: Sort Method: quicksort Memory: ...
EXPLAIN (ANALYZE, BUFFERS)
SELECT * FROM ticket_flights ORDER BY amount DESC;
```

Важно: один запрос может использовать несколько операций одновременно. Много сессий с высоким `work_mem` → OOM.

## 6. Диагностика

### Ожидания и Latches

```sql
SELECT wait_event_type, wait_event, count(*)
FROM pg_stat_activity
WHERE wait_event IS NOT NULL
GROUP BY 1, 2
ORDER BY count DESC;
```

### `pg_stat_statements`

```bash
# один раз на кластер: включить preload и перезапустить контейнер
MSYS_NO_PATHCONV=1 docker exec pg16_check \
  psql -U postgres -c "ALTER SYSTEM SET shared_preload_libraries = 'pg_stat_statements';"
docker restart pg16_check
```

```sql
-- установка расширения в базе demo
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;

-- топ по суммарному времени
SELECT query, calls,
       total_exec_time::numeric(10,2) AS total_ms,
       mean_exec_time::numeric(10,2) AS avg_ms,
       shared_blks_hit, shared_blks_read, temp_blks_written
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 10;

-- сброс статистики
SELECT pg_stat_statements_reset();
```
