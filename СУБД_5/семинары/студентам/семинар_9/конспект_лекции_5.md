# Конспект лекции 5: B+-деревья и индексы в базах данных

## 1. Зачем нужны индексы

Индекс — вспомогательная структура данных «ключ → указатель на строку», ускоряющая поиск ценой дополнительного места и замедления записи. Без индекса — Seq Scan по всем страницам heap.

## 2. B+-дерево: определение и структура

- Сбалансированное n-арное дерево: все листья на одной глубине → O(log n) для любой операции.
- Узел = одна страница (8 КБ в PostgreSQL); внутренние узлы хранят только ключи-разделители, данные (указатели на кортежи, ctid) — только в листьях.
- Листья связаны двусвязным списком → эффективные диапазонные сканирования (`>`, `BETWEEN`, `ORDER BY`).
- **Составные индексы**: работают по левому префиксу (`(a, b)` покрывает `a = ?`, но не `b = ?`).
- Дубликаты и NULL: NULL в PostgreSQL индексируются (можно искать `IS NULL` по B-tree).

## 3. Операции

- **Поиск:** спуск от корня по разделителям, бинарный поиск внутри узла.
- **Вставка:** при переполнении страницы — расщепление (split), ключ-разделитель поднимается вверх; может каскадировать до корня (рост высоты).
- **Удаление:** при недозаполнении — слияние/перебалансировка (в PostgreSQL — отложенная, страницы удаляются vacuum'ом).
- Монотонно возрастающий ключ (SERIAL) → все вставки в «правый» лист → contention на LWLock (см. КР №2, Index Skew).

## 4. Проектные решения

- Размер узла = страница: один disk seek на уровень дерева.
- Ключи переменной длины: префиксное сжатие, суффиксное усечение.
- **Кластеризованный индекс** (порядок строк = порядку ключа: InnoDB PK, `CLUSTER` в PG — разовый) vs **некластеризованный** (heap + указатели).
- Оптимизации: fillfactor, deduplication (PG 13+), covering index (`INCLUDE`) → Index-Only Scan.

## 5. Физическая упаковка страницы индекса

Макет страницы B-tree в PostgreSQL: заголовок → спец. область (opaque) → line pointers → items; правый/левый ссылки соседей; high key.

## 6. Где B+-дерево не работает

| Структура | Задача | Сложность | Применение |
|---|---|---|---|
| **Фильтр Блума** | «ключа точно нет» без хранения ключей | O(k) | LSM-компакции, Cassandra; ложноположительные возможны |
| **Skip-список** | конкурентный in-memory индекс | O(log n) | MemSQL, Redis (sorted set) |
| **Trie** | префиксный поиск строк | O(len(key)) | автодополнение, маршрутизация |
| **Инвертированный индекс** | «в каких документах термин?» | — | полнотекстовый поиск, GIN в PostgreSQL |
| **Векторные ANN-индексы** (HNSW, IVF) | поиск по близости эмбеддингов | приближённый | pgvector, семантический поиск |
