# Конспект семинара №8. Программный доступ к БД (Python, SQLAlchemy, pandas)

## 1. Главная идея

База данных — сервис, с которым приложение общается по сети. Любое обращение к БД стоит ресурсов. Минимизируйте количество запросов и объём передаваемых данных.

## 2. DB-API и соединения

- **DB-API (PEP 249):** стандартный Python-интерфейс. Объекты: `Connection` (транзакции), `Cursor` (запросы).
- **Пул соединений:** кэш открытых TCP-соединений. Создание нового соединения дорого (fork процесса в PostgreSQL). SQLAlchemy использует `QueuePool`, psycopg3 — `psycopg_pool.ConnectionPool`.
- Соединение всегда закрывать (менеджер контекста `with`).

## 3. Транзакции

```python
with psycopg.connect("dbname=demo user=postgres password=postgres") as conn:
    with conn.cursor() as cur:
        cur.execute("INSERT INTO users (name) VALUES (%s)", ("Alice",))
    # commit автоматически при нормальном выходе, rollback при исключении
```

Длительные транзакции — зло: пока транзакция открыта, autovacuum не может очистить старые версии строк (MVCC), таблица раздувается (bloat).

## 4. SQL-инъекции и параметризация

❌ Нельзя использовать f-строки:

```python
cur.execute(f"UPDATE users SET status = 'active' WHERE name = '{name}'")
```

✅ Параметризация:

```python
cur.execute("UPDATE users SET status = 'active' WHERE name = %s", (name,))
```

Данные передаются по бинарному протоколу и не интерпретируются как SQL-код.

## 5. Обработка ошибок

```python
import psycopg
from psycopg.errors import UniqueViolation

try:
    with psycopg.connect(...) as conn:
        ...
except UniqueViolation as e:
    print(f"Ошибка целостности: {e}")
except Exception as e:
    print(f"Неожиданная ошибка: {e}")
```

## 6. SQLAlchemy Core и батчинг

```python
from sqlalchemy import create_engine, text
import pandas as pd

engine = create_engine("postgresql+psycopg://postgres:postgres@localhost:5432/demo")

records = df.to_dict('records')  # список словарей

with engine.connect() as conn:
    conn.execute(
        text("INSERT INTO iot_data (id, name) VALUES (:id, :name)"),
        records  # executemany под капотом
    )
    conn.commit()
```

`executemany` — один сетевой round-trip для множества строк. Не используйте цикл `for row: execute(...)`.

## 7. Pandas

- In-memory аналитика на C/NumPy.
- Для больших таблиц используйте `chunksize` во `pd.read_sql()`, чтобы не словить OOM.

```python
import pandas as pd
import numpy as np

for chunk in pd.read_sql("SELECT * FROM iot_data", engine, chunksize=1000):
    chunk['status'] = np.where(chunk['temperature'] > 30, 'OVERHEAT', 'NORMAL')

```

## 8. SQLAlchemy ORM

### M:N связь

Реализуется через ассоциативную таблицу `Table` и `relationship(secondary=...)`.

### Каскады

- **На уровне БД (`ondelete='CASCADE'`)**: PostgreSQL удаляет связи сам. Быстро.
- **На уровне ORM (`cascade="all, delete-orphan"`)**: ORM загружает объекты и удаляет по одному. Медленно.

Предпочитайте каскады на уровне БД.

### Проблема N+1 и `selectinload`

```python
# плохо: 1 запрос + N запросов
pilots = session.query(Pilot).all()
for p in pilots:
    print(p.aircrafts)

# хорошо: 1 + 1 запрос
from sqlalchemy.orm import selectinload
stmt = select(Pilot).options(selectinload(Pilot.aircrafts))
pilots = session.scalars(stmt).all()
```
