Реализация отношения M:N:
Отношение «Многие-ко-Многому» между курсами (Course) и категориями (Category) декомпозировано с помощью промежуточной связующей таблицы CourseCategory.

Составной первичный ключ PRIMARY KEY (id_course, id_category) исключает дублирование связей и обеспечивает целостность.

Поведение DROP CASCADE:
При выполнении DROP TABLE <таблица> CASCADE база данных автоматически удаляет все связанные FOREIGN KEY ограничения из дочерних таблиц, предотвращая ошибки связи и позволяя безопасно пересоздать структуру.

| № | Ограничение | Выполняемый запрос (SQL) | Сообщение СУБД | Понятное сообщение для пользователя | Как исправить |
|---|---|---|---|---|---|
| 1 | **CHECK** | `INSERT INTO Course (title, price, id_teacher) VALUES ('Курс по Python', -500.00, 1);` | `new row for relation "course" violates check constraint "course_price_check"` | «Цена курса не может быть отрицательной» | Указать корректную цену $\ge 0$ |
| 2 | **FOREIGN KEY** | `INSERT INTO Course (title, price, id_teacher) VALUES ('Основы Java', 1500.00, 9999);` | `insert or update on table "course" violates foreign key constraint "course_id_teacher_fkey"` | «Нельзя создать курс для несуществующего преподавателя» | Указать `id` реально существующего преподавателя из таблицы `Teacher` |

Эффект DROP CASCADE на моем примере:
При удалении самой таблицы CourseCategory CASCADE удаляются внешние ключи и зависимые объекты (индексы), но исходные таблицы Course и Category остаются нетронутыми.   При удалении отдельного курса или категории срабатывает ON DELETE CASCADE на уровне FOREIGN KEY, что автоматически удаляет соответствующую запись-связку из CourseCategory, сохраняя цельность данных без ошибок внешних ключей.
