# КОНСПЕКТ ЛЕКЦИИ №2
## Современный SQL: агрегации, подзапросы, оконные функции, CTE

> Подробности и примеры данных — см. `лекция.md` (тема СУБД_2). Здесь — выжимка для повторения.

---

## 1. Основы

- **SQL** — декларативный язык: описываем *что* получить, СУБД решает *как* (планировщик/оптимизатор).
- Стандарты: SQL-92 (ядро), SQL:2003 (оконные функции), SQL:2016 (JSON), SQL:2023 (графы свойств).
- **Реализации на базе PostgreSQL** (лекция.md, раздел 1.1): **PostgreSQL** — процесс на соединение, MVCC, WAL, стоимостной планировщик; OLTP. **Postgres Pro** — совместимый российский форк (движок/протокол/SQL те же), сертификация ФСТЭК, коммерческая поддержка; демо-БД «Авиаперелёты» — от него. **Greenplum** — MPP shared-nothing на базе PostgreSQL: мастер + сегменты, distribution key, колоночные AO-таблицы; OLAP/DWH. Выбор системы = выбор архитектуры под класс нагрузки.
- **Классы команд:** DML (`SELECT/INSERT/UPDATE/DELETE`), DDL (`CREATE/ALTER/DROP`), DCL (`GRANT/REVOKE`), TCL (`COMMIT/ROLLBACK`).
- Реляционная алгебра оперирует **множествами**, SQL — **мультимножествами** (дубликаты разрешены; убираются `DISTINCT`).
- **Соединения:** `CROSS` (все пары строк), `INNER` (только совпадения), `LEFT`/`RIGHT`/`FULL` (сохраняют строки без совпадений, NULL на пустой стороне). Условие по внешней стороне — в `ON`, не в `WHERE`, иначе `LEFT JOIN` превращается в `INNER` (см. лекция.md, раздел 5).

## 2. Агрегация

- `AVG / MIN / MAX / SUM / COUNT`; `COUNT(*)` считает строки, `COUNT(col)` — только не-NULL; `COUNT(DISTINCT col)` — уникальные.
- Неагрегированный столбец рядом с агрегатом — ошибка (стандарт: `ANY_VALUE`).
- **`GROUP BY`** — группировка; **`HAVING`** — фильтр групп *после* агрегации (`WHERE` — строк *до*).
  Порядок: `WHERE → GROUP BY → HAVING → SELECT → ORDER BY`.
- **`GROUPING SETS`** — несколько группировок одним сканированием (в т.ч. `()` — общий итог).

## 3. Строки, даты, вывод

- `LIKE`: `%` — любая подстрока, `_` — ровно один символ; строки в **одинарных** кавычках, регистр важен.
- Конкатенация — `||`; функции `SUBSTRING/UPPER/LOWER`.
- Работа с датами зависит от диалекта (PostgreSQL: `DATE_PART`, `EXTRACT`).
- Перенаправление вывода: `SELECT ... INTO new_table`, `INSERT INTO t (SELECT ...)`, `INTO TEMPORARY`.
- `ORDER BY` (по умолчанию `ASC`, выражения допустимы) + `LIMIT/OFFSET` (стандарт: `OFFSET ... FETCH FIRST ... ROWS ONLY`). Без `ORDER BY` результат `LIMIT` недетерминирован.

## 4. Оконные функции

- Считают по **скользящему набору строк**, строки не сворачиваются (в отличие от `GROUP BY`).
- Схема: `PARTITION BY` (разделы) → `ORDER BY` внутри `OVER` → рамка окна → функция.
- `ROW_NUMBER()` — сквозная нумерация; `RANK()` — с пропусками при равных значениях (ties); `DENSE_RANK()` — без пропусков. Агрегаты (`SUM`, `AVG`) тоже работают как оконные.
- Паттерн «второе место в группе»: `RANK() OVER (PARTITION BY ... ORDER BY ...)` + фильтр `rank = 2` во внешнем запросе (см. лекция.md, раздел 10).

## 5. Подзапросы

- Места: `SELECT` (скалярный), `FROM` (производная таблица), `WHERE` (`IN/EXISTS/ANY/ALL`).
- `IN` ≡ `= ANY`; `EXISTS` — истина, если подзапрос вернул ≥1 строку.
- Коррелированный подзапрос ссылается на внешний запрос — теоретически O(N²); оптимизатор превращает `IN/EXISTS` в **SEMI-JOIN**, `NOT EXISTS` — в **ANTI-JOIN**.
- 🔴 **Ловушка `NOT IN` + `NULL`:** если подзапрос вернёт `NULL`, весь предикат → `UNKNOWN`, результат пуст. Всегда `NOT EXISTS` (см. лекция.md, раздел 11.3).

## 6. LATERAL

- Подзапрос в `FROM` может ссылаться на таблицы левее — «вложенный цикл» в SQL. Удобен для per-group вычислений и Top-N (см. семинар №4).

## 7. CTE (WITH)

- Именованная временная таблица в рамках одного запроса; несколько CTE через запятую; можно именовать столбцы.
- **`WITH RECURSIVE`** — самоссылка (базовый случай `UNION` рекурсивный шаг); обход иерархий/графов. Делает SQL Тьюринг-полным.

## Ключевые правила

1. Один декларативный запрос вместо процедурного кода — оптимизатор справится.
2. `NOT EXISTS` вместо `NOT IN` — безопасность при NULL.
3. `DISTINCT` и дубликаты — помним про мультимножества.
