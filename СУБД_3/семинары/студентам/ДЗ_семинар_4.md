# Домашнее задание (Семинар 4). Advanced SQL и оптимизация

**Домашнее задание:**

_Общее требование для всех заданий:_ К каждому SQL-запросу вы должны приложить вывод команды `EXPLAIN (ANALYZE, BUFFERS)` и написать краткое аналитическое резюме (2-4 предложения): какие узлы (Nodes) присутствуют в плане, почему оптимизатор выбрал именно их (например, Seq Scan вместо Index Scan), использует ли он индексы, и каково реальное время выполнения.

1. **Группировки и многоуровневые итоги (ROLLUP):** Посчитайте помесячную выручку от продажи билетов за 2017 год вместе с общим итогом — одним запросом, через `ROLLUP`.

    - Оставьте только месяцы с выручкой более 10 млрд рублей (`HAVING`), следя за тем, чтобы итоговая строка при этом не потерялась.
    - Приложите `EXPLAIN ANALYZE`. Объясните, как `HAVING` работает вместе с `ROLLUP` и почему итоговая строка (со значением `NULL` в колонке месяца) проходит фильтр.
2. **LEFT JOIN и условная агрегация:** Для каждого аэропорта прибытия посчитайте число прибывших рейсов (`status = 'Arrived'`), включая аэропорты, куда не прибыл ни один рейс: код аэропорта, название, число рейсов.

    - Важно: условие по статусу перенесите в `ON` соединения, а не в `WHERE`. Продемонстрируйте контрольным запуском, что произойдёт с результатом, если оставить условие в `WHERE`.
    - Приложите `EXPLAIN ANALYZE`. Объясните, почему здесь недопустим `COUNT(*)`, и что означает узел `Hash Right Join` в плане.
3. **Sargability (Оптимизация предикатов):** Найдите все рейсы, выполненные (`status = 'Arrived'`) в выходные дни (суббота и воскресенье) в августе 2017 года.

    - Напишите неоптимизированный запрос с `EXTRACT(DOW FROM ...)` или `TO_CHAR(...)`.
    - Напишите оптимизированный запрос с использованием диапазонов дат.
    - Приложите `EXPLAIN ANALYZE` к обоим. Объясните разницу в планах выполнения.
4. **Оконные функции (Скользящее окно):** Посчитайте скользящее среднее (`AVG`) стоимости билетов (`amount`) за последние 7 дней (по дате вылета) на протяжении всего августа 2017 года.

    - Используйте паттерн с CTE (предварительная агрегация по дням) и рамку `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW`.
    - Приложите `EXPLAIN ANALYZE`. Объясните, зачем нужен был `GROUP BY` в CTE перед применением оконной функции.
5. **LATERAL JOIN против Оконных функций (Top-N):** Для каждого самолета (`aircraft_code` из таблицы `aircrafts`) найдите топ-5 самых дорогих проданных на него билет.

    - Напишите запрос через `RANK() OVER (PARTITION BY aircraft_code...)`.
    - Напишите запрос через `LATERAL JOIN` (может потребоваться создать дополнительный индекс).
    - Приложите `EXPLAIN ANALYZE` к обоим. Объясните, почему LATERAL показывает лучшее время и какие узлы (например, Nested Loop) обеспечивают эту скорость.
6. **CTE MATERIALIZED:** Найдите аэропорты, где средняя задержка рейса (разница между `actual_arrival` и `scheduled_arrival`) превышает среднюю задержку по всем аэропортам.

    - Напишите запрос с использованием CTE.
    - Добавьте `MATERIALIZED` к CTE, затем уберите его.
    - Приложите `EXPLAIN ANALYZE` для обоих случаев. Объясните, как наличие/отсутствие `MATERIALIZED` повлияло на структуру плана (например, появление `CTE Scan` и изменение типов Join).
7. **ANTI-JOIN (Оптимизация отрицания):** Найдите все рейсы, на которые не был продан ни один билет бизнес-класса (`fare_conditions = 'Business'`).

    - Напишите запрос с использованием `NOT IN`.
    - Напишите запрос с использованием `NOT EXISTS`.
    - Приложите `EXPLAIN ANALYZE` к обоим. Объясните, почему `NOT EXISTS` работает эффективнее (Anti Join) и почему `NOT IN` может быть опасен при наличии `NULL` в данных.
8. **Индексное сканирование (Index Only Scan):** Посчитайте количество рейсов для каждого статуса: `SELECT status, COUNT(*) FROM flights GROUP BY status;`

    - Запустите запрос без дополнительных индексов.
    - Создайте покрывающий индекс:

      ```sql
      CREATE INDEX idx_flights_status ON flights(status);
      ```

      _Примечание: для Index Only Scan индекс должен содержать все запрашиваемые поля; для актуальности Visibility Map выполните `VACUUM flights;`._
    - Приложите `EXPLAIN (ANALYZE, BUFFERS)` до и после создания индекса. Объясните, что означает `Index Only Scan` и почему это значительно ускоряет запрос (ссылка на Visibility Map).
