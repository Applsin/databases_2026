Краткая инструкция по запуску
Подготовка: Убедитесь, что у вас запущена СУБД PostgreSQL и развернута базовая структура таблиц из Домашнего задания №1.

Обновление схемы и индексы:

Откройте файл 1_schema_and_indexes.sql в SQL-клиенте (например, DBeaver).

Выполните файл целиком как единый скрипт (в DBeaver: кнопка «Execute SQL Script» или Alt + X). В базу добавятся новые таблицы и индексы.

Запуск демонстрации нарушений:

Откройте файл 2_violations_demo.sql.

Выполните его как единый скрипт (Alt + X).

Перейдите во вкладку вывода сообщений СУБД (Output / Messages / Сведения). Там отобразятся 5 пользовательских уведомлений о перехваченных ошибках целостности.

Объяснение выполненной работы
В рамках данного домашнего задания была расширена и оптимизирована база данных для домена Project Management:

Реализация отношения M:N: Добавлена система тегирования задач. Отношение "многие-ко-многим" реализовано через сущность tag и промежуточную таблицу task_tag. Для внешних ключей задано правило ON DELETE CASCADE, что гарантирует автоматическую очистку связей при удалении задачи или тега и защищает базу от мусорных данных.

Индексирование: Проанализированы частые выборки из ДЗ №1. Созданы B-Tree индексы для внешних ключей (project_id, employee_id, task_id) и полей фильтрации (status_id, deadline). Это предотвращает полное сканирование таблиц (Seq Scan) при аналитических запросах и JOIN-соединениях.

Скрипт перехвата ошибок: Написан анонимный PL/pgSQL блок (DO $$ ...), который тестирует устойчивость базы данных. Скрипт намеренно вызывает 5 типов конфликтов (CHECK, FOREIGN KEY, UNIQUE, NOT NULL, PRIMARY KEY), перехватывает системные исключения и выводит вместо них понятные для пользователя бизнес-сообщения.

Документирование: Заполнена аналитическая таблица с разбором каждого нарушения, оригинальным текстом ошибки PostgreSQL и алгоритмом действий для исправления.
