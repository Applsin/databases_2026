# databases_2026

Репозиторий для сдачи домашних заданий по курсу «Базы данных» (2026).

## Как сдать домашнее задание

### 1. Подготовка

1. Создайте аккаунт на GitHub, если его ещё нет.
2. Сделайте **fork** этого репозитория (кнопка Fork в правом верхнем углу).
3. Клонируйте свой fork на компьютер:
   ```bash
   git clone git@github.com:<ваш-логин>/databases_2026.git
   ```
4. Создайте отдельную ветку для работы:
   ```bash
   git checkout -b <имя-ветки>
   ```

### 2. Выполнение задания

1. Выберите задачу из выданного преподавателем списка.
2. Реализуйте простой первоначальный вариант решения.
3. Сделайте несколько **осмысленных коммитов** (каждый коммит — законченный
   логический шаг с понятным сообщением).
4. Улучшите или ускорьте решение в своей рабочей ветке.
5. Будьте готовы объяснить, что именно вы изменили и почему новый вариант лучше.

В вашем репозитории (fork) должны находиться:

- исходный код программы;
- `git-reflog.txt` — вывод `git reflog` вашей работы;
- краткая инструкция по запуску;
- объяснение выполненной оптимизации.

### 3. Сдача работы

Опубликуйте рабочую ветку в своём fork и создайте Pull Request:

- **откуда:** рабочая ветка вашего fork;
- **куда:** ветка `main` исходного (преподавательского) репозитория.

Прямые пуши в `main` исходного репозитория закрыты — сдача только через PR.

**Название PR (обязательный формат):**

```
[<номер группы>] <ФИО>
```

- `<номер группы>` — в квадратных скобках, строка не более 20 символов;
- `<ФИО>` — ровно три слова, разделённые пробелом (Фамилия Имя Отчество).

Пример: `[15-25] Иванов Иван Иванович`

Формат проверяется автоматически: PR с названием не по шаблону не пройдёт
проверку и не будет принят к ревью.

**Не создавайте draft-PR.** Открывайте Pull Request только тогда, когда
работа полностью готова к проверке.

Описание PR заполняется по шаблону (подставляется автоматически).
Скриншот прохождения Learn Git Branching приложите к описанию PR.

### 4. Ревьюеры

Преподаватели назначаются ревьюерами автоматически. Дополнительно выберите
своего преподавателя в качестве ревьюера:

- группа **17-25**: @TheTonyPub
- группы **15-25, 16-25, 18-25**: @Applsin

### 5. Очерёдность сдачи

- Временем сдачи считается **время создания готового Pull Request**.
- Пустые и незавершённые PR не позволяют занять место в очереди. Если на
  момент создания PR обязательные требования не выполнены, работа
  отправляется на доработку и не считается сданной, пока не внесены все
  исправления.
- Первые пять студентов определяются по времени создания корректно
  оформленных Pull Request.
- Коммиты, добавленные после создания PR, считаются исправлениями и не
  учитываются при определении первоначальной готовности работы.
