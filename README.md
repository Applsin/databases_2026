# Вариант №1. Онлайн-курсы (EdTech)

Разбор задания по моделированию данных: от бизнес-требований к таблицам.

## Бизнес-домен

Платформа онлайн-образования. Пользователи регистрируются, выбирают курсы и
проходят обучение. Курс состоит из нескольких уроков. Преподаватели создают
курсы и получают отчисления от продаж. Студенты оставляют отзывы на курсы и
оценивают их по шкале от 1 до 5.

## Задание 1. Концептуальная модель

Основные сущности и связи между ними (без атрибутов):

- **User** (пользователь: студент или преподаватель)
- **Course** (курс)
- **Lesson** (урок)
- **Enrollment** (запись студента на курс)
- **Review** (отзыв студента на курс)
- **LessonProgress** (прогресс прохождения урока)
- **Payout** (выплата преподавателю)

Связи:

- Преподаватель **создаёт** курсы (один преподаватель — много курсов).
- Студент **записывается** на курсы через Enrollment (многие-ко-многим между
  студентами и курсами).
- Курс **состоит из** уроков (один курс — много уроков).
- Студент **оставляет** отзыв на курс через Review (многие-ко-многим между
  студентами и курсами, но с оценкой и комментарием).
- Студент **проходит** уроки — фиксируется через LessonProgress.
- Преподаватель **получает** выплаты по каждому курсу через Payout.

Каждая связь и сущность выведена напрямую из текста бизнес-требований:
"пользователи регистрируются, выбирают курсы" → User, Course, Enrollment;
"курс состоит из нескольких уроков" → Lesson; "преподаватели создают курсы и
получают отчисления" → Payout; "студенты оставляют отзывы и оценивают" →
Review.

## Задание 2. Логическая модель

Полная схема с атрибутами, первичными (PK) и внешними (FK) ключами показана
на ER-диаграмме (см. отдельный файл/скриншот диаграммы, приложенный к
работе, либо сгенерируйте её на dbdiagram.io/DrawSQL из `schema.sql`).

**Кардинальность связей (нотация "воронья лапка"):**

| Связь | Кардинальность |
|---|---|
| users (teacher) → courses | 1 : N |
| users (student) → enrollments ← courses | 1 : N : 1 (реализует M:N) |
| courses → lessons | 1 : N |
| users (student) → reviews ← courses | 1 : N : 1 (реализует M:N) |
| users (student) → lesson_progress ← lessons | 1 : N : 1 (реализует M:N) |
| users (teacher) → payouts ← courses | 1 : N : 1 |

**Идентифицирующие связи** (дочерняя запись не имеет смысла без родителя,
удаление каскадное): `lessons → courses`, `enrollments → users/courses`,
`reviews → users/courses`, `lesson_progress → users/lessons`,
`payouts → users/courses`.

**Неидентифицирующая связь**: `courses → users (teacher)` — курс логически
связан с преподавателем, но существование курса не обязано рушиться
каскадно при удалении преподавателя, поэтому FK без `ON DELETE CASCADE`.

**Решение по разделению пользователей**: студенты и преподаватели хранятся
в одной таблице `users` с полем `role`, а не через наследование или
отдельные таблицы. Общих атрибутов (имя, почта, дата регистрации) у ролей
больше, чем специфичных, поэтому разделение только усложнило бы схему без
реальной пользы для этого объёма задания.

**Статус завершения**: на уровне урока — таблица `lesson_progress` (сам
факт записи = урок пройден). На уровне курса — поле `status` в
`enrollments` (`in_progress` / `completed` / `cancelled`).

## Задание 3. Физическая модель

SQL-скрипт лежит в файле `schema.sql`. Кратко про решения:

- Все таблицы создаются через `DROP TABLE IF EXISTS ... CASCADE` в начале
  скрипта — повторный запуск не ломается.
- `PRIMARY KEY` — везде `SERIAL PRIMARY KEY`.
- `FOREIGN KEY` — везде, где сущность ссылается на другую (`REFERENCES`).
- `CHECK` — ограничивает роль пользователя, диапазон оценки (1–5), цену и
  сумму выплаты (не отрицательные), статус записи на курс, порядковый номер
  урока.
- `NOT NULL` — на всех обязательных по смыслу полях.
- `UNIQUE` — email пользователя; пара (студент, курс) в `enrollments` и
  `reviews`, чтобы нельзя было записаться/оставить отзыв дважды; пара
  (курс, номер урока) в `lessons`.
- Индексы созданы на все внешние ключи (`idx_*`) — это ускоряет JOIN'ы
  между таблицами, которые неизбежны почти в каждом запросе ниже.

## Задание 4. Частые запросы к базе данных

1. Вывести список всех курсов с количеством записавшихся студентов.
2. Найти 10 самых популярных курсов по количеству отзывов и средней оценке.
3. Показать все уроки конкретного курса в правильном порядке
   (сортировка по `order_number`).
4. Получить историю обучения студента: какие курсы он проходит/прошёл
   (через `enrollments.status`) и какие оценки он им поставил
   (через `reviews`).
5. Рассчитать сумму, которую должен получить преподаватель за месяц по
   всем своим курсам (сумма по `payouts` за период, сгруппированная по
   `teacher_id`).

## Как запустить

1. Поднимите PostgreSQL в Docker по инструкции курса
   (`Установка Postgresql на машине.md`).
2. Выполните скрипт:
   ```bash
   psql -h localhost -U <ваш_пользователь> -d <ваша_база> -f schema.sql
   ```
3. Скрипт можно запускать повторно — каждый раз таблицы будут пересозданы
   с нуля.
