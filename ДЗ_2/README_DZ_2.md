# Домашнее задание №2 — EdTech

## Основа

ДЗ №2 продолжает физическую модель из ДЗ №1 для варианта №1 «Онлайн-курсы (EdTech)».

В ДЗ №1 были таблицы:

- `users`
- `courses`
- `lessons`
- `enrollments`
- `reviews`

В ДЗ №2 добавлены:

- `lesson_progress`
- `payments`

## Часть 1. Дополнение схемы

### `lesson_progress`

Таблица хранит прогресс пользователя по конкретному уроку.

- `user_id` — пользователь;
- `lesson_id` — урок;
- `status` — `in_progress` или `completed`;
- `completed_at` — время завершения.

Ограничения:

- `PRIMARY KEY (user_id, lesson_id)` — один объект прогресса на пару пользователь–урок;
- FK на `users` и `lessons`;
- `NOT NULL` для обязательных полей;
- `CHECK` для статуса;
- дополнительный `CHECK` связывает статус и время завершения.

Логическая связь User M:N Lesson реализована промежуточной таблицей `lesson_progress`.

При `ON DELETE CASCADE` удаление пользователя удаляет его прогресс, а удаление урока — прогресс по этому уроку. Это предотвращает «осиротевшие» записи.

### `payments`

Таблица хранит оплаты пользователей за курсы.

- `payment_id` — идентификатор оплаты;
- `user_id` — пользователь;
- `course_id` — оплаченный курс;
- `amount` — сумма;
- `paid_at` — время оплаты;
- `status` — статус платежа.

Ограничения:

- `PRIMARY KEY (payment_id)`;
- FK на `users` и `courses`;
- `NOT NULL`;
- `CHECK (amount > 0)`;
- `CHECK` для статуса;
- `UNIQUE (user_id, course_id, paid_at)` — защита от точного дублирования оплаты.

## Индексы

Добавлены:

- `lesson_progress(user_id)`
- `lesson_progress(lesson_id)`
- `lesson_progress(user_id, status)`
- `payments(course_id, paid_at)`
- `payments(user_id, paid_at)`

В ДЗ №1 уже есть индексы на FK:

- `courses(teacher_id)`

Они поддерживают частые запросы из ДЗ №1: поиск курсов и студентов, отзывы, уроки курса, историю обучения и расчёт выплат преподавателю.

## Часть 2. Демонстрация нарушений

Файл `dz2_constraints_demo.sql` содержит **ровно 5 демонстраций**:

| № | Ограничение | Что нарушается | Понятное бизнес-сообщение | Как исправить |
|---|---|---|---|---|
| 1 | CHECK | Недопустимый статус прогресса | Статус должен быть `in_progress` или `completed` | Указать допустимый статус |
| 2 | FOREIGN KEY | Несуществующий пользователь | Нельзя сохранить прогресс несуществующего пользователя | Указать существующего пользователя |
| 3 | UNIQUE | Дубликат оплаты | Нельзя создать дубликат одной и той же оплаты | Использовать другую запись оплаты |
| 4 | NOT NULL | `amount = NULL` | Сумма оплаты обязательна | Указать сумму |
| 5 | PRIMARY KEY | Повторная пара `(user_id, lesson_id)` | Для одного пользователя и урока допустима одна запись прогресса | Изменить существующую запись |

Каждый блок использует `DO $$ ... EXCEPTION ... END $$` и выводит исходный текст ошибки PostgreSQL через `SQLERRM`.

## Часть 3. Вывод

Схема ДЗ №1 расширена двумя таблицами. `lesson_progress` хранит состояние обучения и реализует M:N между пользователями и уроками. `payments` хранит оплаты и позволяет рассчитывать выплаты преподавателю за период.

Ограничения обеспечивают целостность данных, а индексы поддерживают частые запросы из ДЗ №1 и операции поиска по пользователю, уроку, курсу и времени оплаты.
