\## 1. Концептуальная модель

На концептуальном уровне выделены основные сущности предметной области:

* \*\*User (Пользователь)\*\* — может выступать в роли студента или инструктора.
* \*\*Course (Курс)\*\* — образовательный продукт, создаваемый инструктором.
* \*\*Lesson (Урок)\*\* — составная часть курса.
* \*\*Enrollment (Запись на курс)\*\* — факт покупки/записи студента на курс.
* \*\*Review (Отзыв)\*\* — оценка и текстовый отзыв, оставленный студентом о курсе.

\*\*Основные связи:\*\*

* Инструктор (User) создает много курсов (Course) — 1:N.
* Курс (Course) содержит много уроков (Lesson) — 1:N.
* Студент (User) может записаться на много курсов (Enrollment) — 1:N.
* Студент (User) может оставить много отзывов (Review) — 1:N.

\## 2. Логическая модель

Логическая модель детализирует концептуальную, определяя атрибуты, типы данных и ограничения:

* \*\*users\*\*: хранит данные пользователей. `email` уникален, `password` обязателен.
* \*\*courses\*\*: содержит информацию о курсах. Привязан к инструктору через `instructor\_id`.
* \*\*lessons\*\*: уроки курса. Привязаны к курсу через `course\_id`, есть порядковый номер `lesson\_order`.
* \*\*enrollments\*\*: записи студентов. Ограничение `UNIQUE(student\_id, course\_id)` запрещает дублирование записей.
* \*\*reviews\*\*: отзывы. Оценка `rating` ограничена диапазоном от 1 до 5. Ограничение `UNIQUE(course\_id, student\_id)` не дает оставить более одного отзыва на курс.

\## 3. Физическая модель (SQL)

Физическая модель реализована в виде SQL-скрипта `schema.sql` для СУБД \*\*PostgreSQL\*\*.

\*\*Реализованные требования к БД:\*\*

* \*\*Первичные ключи (PRIMARY KEY)\*\*: Для всех таблиц используются суррогатные ключи `SERIAL`.
* \*\*Внешние ключи (FOREIGN KEY)\*\*: Настроены связи между таблицами. Для уроков, записей и отзывов используется `ON DELETE CASCADE` (при удалении курса удаляется всё связанное). Для инструктора — `ON DELETE RESTRICT` (нельзя удалить пользователя, если у него есть курсы).
* \*\*Ограничения (CHECK, UNIQUE, NOT NULL)\*\*:
* `email` в таблице `users` — уникален.
* `rating` в таблице `reviews` — `CHECK (rating >= 1 AND rating <= 5)`.
* Составные уникальные ключи: `UNIQUE(student\_id, course\_id)` в `enrollments` и `UNIQUE(course\_id, student\_id)` в `reviews`.
* \*\*Индексы\*\*: Добавлены индексы на все внешние ключи (`instructor\_id`, `course\_id`, `student\_id`) для ускорения JOIN-запросов.
