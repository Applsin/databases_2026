## 1. Параметризованный поиск

Значение передаётся отдельно от SQL через `%s` и кортеж параметров. Поиск apple вернул `(1, 'apple', 10)`. Ввод `apple' OR '1'='1` вернул пустой список: значение воспринимается как данные, а не условие SQL.

## 2. Атомарность транзакции

Таблица ex2 создана в отдельной транзакции. При вставке строк с идентификаторами 1, 2 и повторно 1 возникло UniqueViolation. После отката в таблице 0 строк: первые две вставки тоже отменены. В psycopg 3 контекст соединения выполняет commit при нормальном выходе, rollback при исключении и закрывает соединение.

## 3. Исправление SQL-инъекции

Функция broken собирает условие через f-строку и при вводе `' OR '1'='1` возвращает обе строки. В fixed используется параметризация и LIMIT 5; тот же ввод возвращает `[]`. Ограничение LIMIT само по себе от инъекции не защищает.

## 4. Пакетная вставка

Для одного замера на 10 000 строк получено 0,73 с для цикла и 0,08 с для executemany, ускорение около 8,9 раза. Дополнительно проведено по три замера для каждого размера с чередованием порядка методов. Между вставками таблица очищается; число записей проверяется через assert.

| Строк | Медиана цикла, с | Медиана executemany, с | Ускорение |
|---:|---:|---:|---:|
| 100 | 0,0220 | 0,0097 | 2,28 |
| 1 000 | 0,0830 | 0,0167 | 4,95 |
| 10 000 | 0,7026 | 0,0807 | 8,71 |

На всех трёх размерах executemany был быстрее в каждом повторе. Наименьший проверенный размер — 100 строк; точный порог ниже этого размера не исследовался. Ускорение не равно числу строк: остаются обработка INSERT сервером, индексы, WAL и фиксация транзакции. Один вызов executemany не означает один SQL-запрос. Время зависит от нагрузки и окружения.

## 5. SQLAlchemy Core

Через text() создана ex5_measurements и одним вызовом execute со списком словарей вставлены 200 строк. Значение равно `i * 0.7`, сенсор — `S{i % 4}`. После commit запрос `value > 50` вернул 129 строк. Параметры передаются отдельно от SQL.

## 7. Связь многие-ко-многим

Author и Book связаны через author_book с составным первичным ключом и внешними ключами ON DELETE CASCADE. Созданы два автора и три книги. Общая книга представлена одним объектом Book, добавленным обоим авторам. До удаления автора было четыре связи, после — две; все три книги остались.

В учебном решении два объекта с одинаковым названием создавали две разные книги. В рабочей копии это исправлено. При удалении через Session ORM также может удалять строки связи самостоятельно: итоговый счётчик подтверждает результат удаления, но не доказывает отсутствие дополнительных ORM-запросов. Для передачи удаления незагруженных связей БД применяется согласованная настройка passive_deletes и ON DELETE CASCADE.

## 8. N+1 и joinedload

Для пяти пилотов обычная ленивая загрузка выполнила 6 запросов, selectinload — 2, joinedload — 1. При joinedload коллекции используется `s.scalars(stmt).unique().all()`: JOIN повторяет родительские строки, поэтому требуется устранение повторений объектов. Selectinload полезен для больших коллекций, поскольку не дублирует колонки родителя в каждой строке JOIN. На больших наборах число его запросов может быть больше двух.
