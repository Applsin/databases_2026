## Таблица нарушений

| № | Ограничение | Выполняемый запрос (SQL)                                                                                         | Сообщение СУБД                                                                               | Понятное сообщение для пользователя                                                                  | Как исправить                                                           |
|---|-------------|------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------|
| 1 | CHECK       | `INSERT INTO review (user_id, restaurant_id, rating) VALUES (1, 1, 10);`                                         | `new row for relation "review" violates check constraint "review_rating_check"`              | «Оценка в отзыве должна быть от 1 до 5. Оценка 10 - недопустима»                                     | Указать оценку в диапазоне 1–5                                          |
| 2 | FOREIGN KEY | `INSERT INTO address (user_id, city) VALUES (999, 'Санкт-Петербург');`                                           | `insert or update on table "address" violates foreign key constraint "address_user_id_fkey"` | «Нельзя привязать адрес к несуществующему пользователю. Адрес должен принадлежать реальному клиенту» | Сначала создать пользователя с `user_id = 999`, затем вставлять адрес   |
| 3 | UNIQUE      | `INSERT INTO "user" (full_name, phone, email) VALUES ('Олег', '+79990000003', 'oleg@mail.ru');`                  | `duplicate key value violates unique constraint "user_phone_key"`                            | «Пользователь с таким телефоном уже зарегистрирован. Телефон должен быть уникальным»                 | Указать другой номер телефона                                           |
| 4 | NOT NULL    | `INSERT INTO "order" (restaurant_id, address_id, total_amount) VALUES (1, 1, 500);`                              | `null value in column "user_id" of relation "order" violates not-null constraint`            | «Нельзя создать заказ без указания клиента. Заказ должен принадлежать пользователю»                  | Указать `user_id` существующего пользователя                            |
| 5 | PRIMARY KEY | `INSERT INTO "user" (user_id, full_name, phone, email) VALUES (100, 'Дубликат', '+79990000101', 'dup@mail.ru');` | `duplicate key value violates unique constraint "user_pkey"`                                 | «Пользователь с таким ID уже существует. Первичный ключ должен быть уникальным»                      | Использовать другой `user_id` (или не указывать его - сработает SERIAL) |

## Краткие выводы

1. **CHECK** защищает от бессмысленных значений (например, оценка вне 1–5). Без него в БД могли бы попасть оценки 10,
   −3, 999.
2. **FOREIGN KEY** обеспечивает ссылочную целостность: нельзя создать адрес, отзыв или заказ, ссылающийся на
   несуществующего родителя.
3. **UNIQUE** не даёт зарегистрировать двух пользователей с одинаковым телефоном или email - это критично для
   идентификации клиента.
4. **NOT NULL** гарантирует, что обязательные поля заполнены: заказ не может быть без клиента, адрес - без города.
5. **PRIMARY KEY** гарантирует уникальность идентификатора каждой строки; попытка вставить дубликат `user_id`
   отклоняется.
6. Все 5 ограничений работают **на уровне СУБД**, а не приложения - это надёжнее, чем проверки в коде.
7. При нарушении PostgreSQL возвращает **понятную ошибку**, которую можно перехватить в `DO $$ ... EXCEPTION ... $$` и
   превратить в человекочитаемое сообщение.

## Проверка индексов под частые запросы из ДЗ №1

| № | Частый запрос             | Индекс                                                 | Покрытие |
|---|---------------------------|--------------------------------------------------------|----------|

| 2 | Средний рейтинг ресторана | `idx_review_restaurant_rating (restaurant_id, rating)` | да       |
